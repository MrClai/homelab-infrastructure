# Decisions

Краткий список решений и причин, почему в homelab выбраны именно эти инструменты.

## k3s

Выбран как лёгкий Kubernetes для домашней инфраструктуры.

Почему:

- проще и легче классического kubeadm-кластера;
- хорошо подходит для Raspberry Pi и небольших x86-нод;
- из коробки есть CoreDNS, Traefik, metrics-server и local-path-provisioner;
- достаточно близок к Kubernetes, чтобы изучать реальные принципы работы кластера.

Ограничение: текущий control-plane не является отказоустойчивым.

## Proxmox VE

Используется как гипервизор для виртуальных машин.

Почему:

- удобное управление VM;
- хорошо подходит для homelab;
- можно развивать в сторону Terraform и автоматизации;
- проще изолировать сервисы по VM.

## ArgoCD

Используется для GitOps-доставки Kubernetes workload.

Почему:

- Git становится источником желаемого состояния;
- видно drift detection;
- удобно объяснять и проверять delivery flow;
- хорошо сочетается с Gitea и CI.

## OpenBao

Используется как secrets manager.

Почему:

- совместим с Vault-подходом;
- open-source;
- подходит для практики Kubernetes auth и secret injection;
- позволяет не хранить секреты в Git.

## FRP

Используется для удалённого доступа через VPS.

Почему:

- помогает обойти double NAT;
- не требует проброса портов на домашнем роутере;
- даёт контролируемую точку входа через VPS.

Ограничение: VPS становится важной точкой для внешнего доступа.

## NFS

Используется для persistent volumes в Kubernetes.

Почему:

- просто настроить;
- понятно дебажить;
- достаточно для homelab и мониторинга.

Ограничение: NFS-хост является точкой отказа, поэтому нужен backup/restore.

## GL-MT6000

Используется как основной роутер домашней сети.

Почему:

- централизованное управление DHCP, DNS и firewall в одном месте;
- OpenWRT под капотом — гибкая настройка зон и правил;
- firewall rules описываются по зонам, host firewall остаётся вторым слоем защиты;
- сеть стала понятнее: одна точка управления вместо нескольких.
